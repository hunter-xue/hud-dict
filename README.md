# HudDict

**English** | [简体中文](README.zh-CN.md)

A macOS menu-bar floating dictionary. Summon the panel with a hotkey or the menu-bar icon, type a word, a sentence, or a short passage, press Enter, and get a **translation** and a **brief explanation** streamed back. Looked-up words are recorded in a local wordbook.

It is **not** a selection tool and **not** screen translation: it does not read selections, does not recognize the screen, and does not request Accessibility or Screen Recording permissions.

> **About this project**: This is a **vibe coding** result. The author is **completely new** to macOS, Swift, and Xcode development (currently learning). The feature design, architecture decisions, and review were done by a human; the vast majority of the code was generated by AI. Please evaluate its quality and suitability accordingly.

## Features

### Floating panel

- Summoned by the menu-bar icon or a global hotkey (default **⌘⌥⇧D**, configurable in Settings).
- Always above other windows, follows all desktops, and can cover borderless full-screen windows.
- Translucent with adjustable opacity, draggable; the drag handle is at the top of the window.
- Does **not** steal focus when shown: the previous app stays frontmost, the menu bar does not switch, and the Dock does not jump. The panel can still receive keyboard input.
- Clears its previous content on show, treating each summon as a fresh query; hide with Esc or by clicking the menu-bar icon again (the process stays alive).

### Query & output

- Accepts arbitrary short text (a word, a sentence, a short passage).
- Fixed two-section output: **translation**, then a **brief explanation** (part of speech / sentence structure, meaning in context, one usage note or commonly confused point).
- Streamed: the translation appears first, the explanation follows. Can be cancelled mid-submit (cancelling keeps what has already streamed in).
- Language direction is auto-detected. Target language defaults to Simplified Chinese and is configurable (the same setting drives both translation and explanation).
- On failure (offline, bad key, API error) the reason is shown inside the panel, never as a system alert.

### LLM settings

- Supports only the OpenAI-compatible Chat Completions API, configured by the user:
  - **Base URL** (e.g. `https://api.openai.com`; the app requests `{Base URL}/v1/chat/completions`, and a trailing `/` or `/v1` is normalized automatically)
  - **Model name**
  - **API Key** (stored in Keychain; the UI only shows "saved / not saved" and never echoes it; saving an empty field keeps the existing key, and there is a separate "Clear" button)
- All three are required. If incomplete, **no request is sent** — the panel prompts you to finish setup.
- You can send a short **connection test** before saving; failures are shown on the settings page.

So services compatible with that path — xAI, DeepSeek, Ollama, LM Studio, etc. — all work. Anthropic / Gemini native APIs and the OpenAI Responses API are not supported in this version.

### Wordbook

- Recorded **only after a successful query**; failed queries do not count.
- Records **words only**, not phrases or full sentences: judged as, after trimming, containing no whitespace, bounded in length (Latin ≤ 40 / CJK ≤ 20 characters), and with no sentence-ending punctuation.
- The same word merges into one entry: Latin letters are case-insensitive (`Word` == `word`); Chinese/Japanese merge as-is.
- Each entry stores: surface form, count, last-query time, last translation (no explanation).
- Viewed in a separate window: sorted by count descending, then by last-query time descending; filter by word, delete individual entries.
- Exportable to Markdown (word, count, last-query time, last translation), with a user-chosen save location.
- Stored locally under Application Support as JSON; never uploaded, never synced.

### Settings

LLM settings, hotkey, target language, opacity, wordbook, quit.

## Requirements

- macOS 14 or later
- Full Xcode (Command Line Tools alone are not enough)
- [XcodeGen](https://github.com/yonaskolb/XcodeGen): `brew install xcodegen` (used to generate the project)

## Build & run

The Xcode project is generated from `project.yml`; `HudDict.xcodeproj` is **not committed**:

```sh
make generate   # generate HudDict.xcodeproj from project.yml
make build      # xcodebuild Debug build (output in DerivedData)
make run        # compile and run directly with swiftc (no xcodebuild needed)
```

You can also run `make generate` and then open `HudDict.xcodeproj` in Xcode.

## Architecture

Strictly two layers; the window layer never leaks into the business layer:

| Directory | Responsibility | AppKit |
|---|---|---|
| `HudDict/HUDPanel` | Floating panel: show/hide, top-most, opacity, drag, non-activating | Yes |
| `HudDict/ExplainClient` | Prompt assembly, streaming request, split translation vs. explanation | **No** |
| `HudDict/WordBook` | Record words, count, last-query time, Markdown string | **No** |
| `HudDict/Settings` | Settings window, Keychain, UserDefaults, connection test | Yes |
| `HudDict/WordBookUI` | Wordbook window, export (`NSSavePanel`) | Yes |
| `HudDict/HotKey` | Carbon `RegisterEventHotKey` global hotkey | Yes |
| `HudDict/App` | Entry point, menu bar, wiring | Yes |

**Key constraint**: `ExplainClient` and `WordBook` must not `import AppKit` (enforced by `make layering`). File picking (`NSSavePanel`) belongs to the window layer; `WordBook` only produces a Markdown **string**.

### Code entry points

- The program entry point is `HudDict/App/main.swift` (top-level code must live in a file named `main.swift`), with startup wrapped in `MainActor.assumeIsolated`.
- Panel dragging is handled by an AppKit overlay, `WindowDragStrip` (SwiftUI content swallows mouse events, so `isMovableByWindowBackground` alone is not enough).

### Streaming output protocol

The model is asked to output `translation <<<SPLIT>>> explanation`, and the client splits it incrementally with `StreamSplitter`:
- content before the marker is the translation, after it is the explanation;
- if the whole stream has no marker, it degrades to "everything as translation, explanation empty" (`missingMarker == true`), without crashing or mis-splitting.
