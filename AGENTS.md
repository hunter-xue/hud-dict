# AGENTS.md

A macOS menu-bar dictionary app (product name: `HudDict`). Requirements live in
`docs/macos-hud-dictionary-requirements.md` and confirmed decisions in
`docs/macos-hud-dictionary-implementation-decisions.md` (both Chinese) — read them before
implementing. This file only records what an agent would otherwise get wrong.

## Build / test

- The Xcode project is **generated by XcodeGen** from `project.yml`. Do not hand-edit
  `HudDict.xcodeproj`; edit `project.yml` and run `make generate` (`xcodegen generate`).
- Prefer the Makefile targets — they are verified to work in this repo:
  - `make typecheck` — `swiftc -typecheck` over all sources (no Xcode needed)
  - `make test` — compiles only the pure-logic sources + `Tests/HudDictTests/main.swift` and runs them
  - `make layering` — fails if `ExplainClient/` or `WordBook/` import AppKit
  - `make build` — `xcodebuild` Debug build (produces `HudDict.app` in DerivedData)
- `make build` / `xcodebuild` requires a working full Xcode; if it fails with a broken
  `IDESimulatorFoundation` plugin, run `xcodebuild -runFirstLaunch`. `make typecheck` / `make test`
  (plain `swiftc`) work without Xcode and are the fastest way to verify a change.
- Tests are a hand-rolled assert harness (no XCTest) so they run without Xcode. Exit code 0 = pass.
- The app entry point is `HudDict/App/main.swift` (top-level code must live in `main.swift`, not
  any other filename). It wraps startup in `MainActor.assumeIsolated`.

## Scope guardrails

The requirements doc has an explicit "明确不做 / out of scope" section (section 9). Do **not** add, suggest, or scaffold any of:

- Text selection capture, Accessibility API, screen OCR / screen recording
- Click-through windows, clipboard monitoring, hover lookup
- Review / spaced-repetition / familiarity / reminders
- Sentence-level query history
- OpenAI Responses API, Anthropic / Gemini native APIs, any non-`v1/chat/completions` protocol
- Windows / Linux / mobile, or a self-hosted backend

Do not request Accessibility or Screen Recording permissions. The app must work without them.

## Architecture (two layers, strictly separated)

- `HUDPanel` — macOS/AppKit only. Panel show/hide/top-most/opacity/drag/non-activating.
- `ExplainClient` — prompts, streaming request, split into translation + explanation. **Must not import AppKit.**
- `WordBook` — record words, counters, last-query time, Markdown export. **Must not import AppKit.**

Keep the window layer out of the business layer. If a change makes `ExplainClient` or `WordBook`
reference AppKit, it is wrong.

## Platform / toolchain

- macOS 14+ only. Native Swift.
- Window: AppKit `NSPanel` with SwiftUI content via `NSHostingView`.
- Menu-bar app: `Info.plist` `LSUIElement = true` (no Dock, no `⌘Tab`).
- Global hotkey: Carbon `RegisterEventHotKey` (or KeyboardShortcuts lib). **Not** `CGEvent` monitors.
- Full Xcode is required to build; Command Line Tools alone are insufficient.

## Window behavior (non-obvious)

- `styleMask` must include `.nonactivatingPanel`; the panel becomes key and receives keyboard
  input while the app itself stays inactive (menu bar / foreground app unchanged).
- `level = .floating`; `collectionBehavior` includes `.canJoinAllSpaces` and `.fullScreenAuxiliary`.
- `hidesOnDeactivate = false`.
- Show with `orderFrontRegardless`, never an activating show.
- Click-through is intentionally **not** implemented — the panel eats mouse events over its area.

## LLM request contract

- Only `POST {Base URL}/v1/chat/completions`, `Authorization: Bearer {API Key}`, JSON body, `stream: true`.
- Normalize `Base URL`: strip a trailing `/` or `/v1` so you never build `/v1/v1`.
- Parse only SSE `data:` lines and the `[DONE]` terminator.
- API Key in Keychain, never in plaintext config; UI shows saved/not-saved, never echoes the full key.
  Empty key field on save = keep the existing key; "清除" deletes it.
- All three fields (Base URL, model, key) are required. If incomplete, do **not** send — show an
  in-panel prompt to finish setup.
- Errors surface inside the panel (or settings page for the connectivity test), never as system alerts.

## Streaming split protocol

- Output is two sections: translation, then explanation. The prompt asks the model to separate them
  with a marker line `<<<SPLIT>>>` (`StreamSplitter.marker`).
- `StreamSplitter` incrementally splits on the marker; if the stream ends with no marker it degrades
  to "all translation + empty explanation" (`missingMarker == true`). Do not switch to JSON output.
- One "目标语言" setting drives **both** translation and explanation language.

## WordBook rules

- Record **only** on a successful query; failures do not increment. Write to disk **immediately** on
  each successful record (JSON in Application Support); a save failure calls `onSaveError`, never
  silently drops.
- A "word" is recordable only if, after trimming: no internal whitespace, no sentence-ending
  punctuation (`。！？.!?；;…`), and length ≤ 40 (Latin) / ≤ 20 (CJK). See `WordNormalizer`.
- Merge by word: Latin letters case-insensitive (`Word` == `word`); CJK merged as-is.
- Per entry store only: surface form (latest spelling), count, last-query time (overwrite, no history),
  latest translation (no explanation text, no old translations).
- `WordBook`/`MarkdownExporter` only produce strings; file picking (`NSSavePanel`) belongs in
  `WordBookUI`. Sort: count desc, then last-query time desc.

## Conventions

- Requirements doc is the source of truth; `implementation-decisions.md` clarifies ambiguities.
- Comments and UI copy are in Simplified Chinese, matching the docs.
- The three modules are `HUDPanel` (AppKit/SwiftUI), `ExplainClient`, `WordBook`; `Settings/`,
  `WordBookUI/`, `HotKey/`, `App/` are window/glue layers where AppKit is allowed.
