## 悬浮小窗高度随内容自适应

### 背景

第一版悬浮小窗为**固定尺寸 420×300**：

- `HUDPanel` 的 `contentRect` 固定为 420×300（`PanelController`）。
- SwiftUI 内容 `PanelView` 用 `.frame(width: 420, height: 300)` 固定。
- 输入框用 `.frame(maxWidth: .infinity)` 固定为满宽，宽度不随文本变化。

固定尺寸顺带修复了一个 bug：输入框背景框曾随内容变宽、删短后不回缩，留下一个"残留框"（详见相关提交）。

### 想法：高度随内容增长

当译文/讲解较长（或输入框改为多行）时，希望窗口**高度自动增长**以完整显示内容，而不是截断或滚动。

### 需要做的事（评估）

1. **输入框多行**：把 `TextField` 换成支持换行的方案 —— `TextField(..., axis: .vertical)` 或 `TextEditor`，高度随行数增长。
2. **动态测高**：用 `NSHostingView` 的 `fittingSize` / `sizeThatFits` 计算 SwiftUI 内容所需高度。
3. **面板 resize**：在内容高度变化时调整 `HUDPanel` 的 `setContentSize` / `setFrame`，注意保持**顶部原点固定**（窗口向下生长，而非向上跳动）。
4. **上限与滚动**：设置最大高度上限，超过后译文/讲解区内部滚动，避免窗口占满屏幕。
5. **与拖动/置顶/不激活的兼容性**：确认 resize 过程中不打断拖动、不激活应用。

### 代价与风险

- 需要在内容变化时频繁测量与 resize，可能与半透明面板的重绘特性交互，出现闪烁。
- 面板生长方向、屏幕边界处理较繁琐。
- 与"呼出即清空"配合时要注意先收缩到初始尺寸再显示。

### 当前状态

**暂不实现**。第一版保持固定尺寸 420×300。
