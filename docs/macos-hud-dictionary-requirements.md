# macOS 悬浮词典 — 需求说明

状态：已收敛，可进入实现。范围只覆盖第一版。

## 1. 产品

一个住在菜单栏里的 macOS 词典小窗。热键或菜单栏图标把它叫出来，粘贴或手打一段文字，回车后流式返回译文和简短讲解。小窗置顶、半透明、可拖，打字时不把原来的应用挤出前台。

查过的单词记入单词本：每个词一个计数、一个最近查询时间。这是查询记录，不是复习或背单词。

它不是划词工具，也不是屏幕翻译。不读选区，不识屏，不申请辅助功能或录屏权限。

## 2. 平台与技术

- 只做 macOS 14 及以上。Windows、Linux、iOS、Android 不在本版。
- 原生 Swift。窗口用 AppKit `NSPanel`，面板内容用 SwiftUI，经 `NSHostingView` 嵌入。
- 菜单栏应用。`Info.plist` 设 `LSUIElement = true`：不进 Dock，不出现在 `⌘Tab`。
- 全局热键用 Carbon `RegisterEventHotKey`（可用 KeyboardShortcuts）。不使用需要辅助功能权限的 `CGEvent` 监听。
- 模型请求只走用户配置的 OpenAI 兼容接口，见第 6 节。密钥放 Keychain，不进明文配置。
- 单词本存在本机 Application Support 目录，JSON 即可。不上传，不同步。
- 需要完整 Xcode 编译。Command Line Tools 不够。

两层分开，窗口层不进业务层：

- `HUDPanel`：显示、隐藏、置顶、透明度、拖动、不激活。只存在于 macOS。
- `ExplainClient`：组提示词、发起流式请求、把结果拆成译文和讲解。不引用 AppKit。
- `WordBook`：记词、加计数、更新最近查询时间、导出 Markdown。不引用 AppKit。

## 3. 窗口行为

本版要的是不抢前台，不是点击穿透。

- 始终在普通窗口之上：`level = .floating`。
- 跟随所有桌面，并能盖住全屏窗口：`collectionBehavior` 包含 `.canJoinAllSpaces` 和 `.fullScreenAuxiliary`。
- 半透明。用整窗透明度；毛玻璃可以做，但不是第一版的验收项。透明度要能调，文字仍可读。
- 可拖。无边框或只留一条可拖区域，避免标准标题栏抢视觉。
- 不激活面板：`styleMask` 含 `.nonactivatingPanel`。小窗可以成为关键窗口并接收键盘，应用本身不激活。菜单栏不切换，Dock 不跳，原来的应用仍是前台。
- `hidesOnDeactivate = false`。切到别的应用时小窗不藏。
- 呼出用 `orderFrontRegardless`，不用会激活应用的显示方式。
- 独占全屏的游戏不保证能盖住。无边框全屏在承诺范围内。

点击穿透不做。小窗盖住的区域会吃掉鼠标，进度条和按钮要点小窗外面，或先把小窗挪开。

## 4. 交互

- 入口有两个：菜单栏图标，和一把全局热键。热键可改。
- 呼出后焦点进入输入框，可以直接打字或粘贴。
- 回车提交。提交中可取消。
- 隐藏：Esc，或菜单栏图标再点一次。隐藏不退出进程。
- 粘贴走输入框自己的粘贴，不监视系统剪贴板，也不在后台自动翻译剪贴板。
- 窗口位置在本次运行期间保持。记住上次位置可以做，不作为验收项。

## 5. 翻译与讲解

- 输入是任意短文本：一个词、一句、一小段。不设文档或文件翻译。
- 输出固定两段：译文，然后简短讲解。讲解包含词性或句式、当前语境下的含义、一条用法或易混点。不要长文。
- 语言方向自动判断。默认讲解语言为简体中文。目标语言可在设置里改。
- 流式显示。先出译文，讲解接着出。失败时在面板里给原因，不弹系统告警。
- 请求使用第 6 节的 LLM 设置。未配置完整时不发请求，面板提示先完成设置。

## 6. LLM 设置

用户自己配置模型接口。第一版只支持 OpenAI 兼容的 Chat Completions，不内置供应商账号，也不接各家私有 SDK。

从菜单栏打开设置，字段如下：

- Base URL。服务根地址，例如 `https://api.openai.com`。程序请求 `{Base URL}/v1/chat/completions`。末尾已有的 `/` 或 `/v1` 要规范化，避免拼成 `/v1/v1`。
- 模型名。原样放进请求体的 `model`。
- API Key。存 Keychain。界面只显示已保存或未保存，不明文回显完整密钥。

协议范围：

- 只发 `POST {Base URL}/v1/chat/completions`。
- 请求头 `Authorization: Bearer {API Key}`，体为 JSON，`stream: true`。
- 只解析 SSE 的 `data:` 行，以及结束标记 `[DONE]`。
- 因此 xAI、DeepSeek、Ollama、LM Studio 等兼容该路径的服务都能用。Anthropic 原生接口、Gemini 原生接口、OpenAI Responses API 本版不支持。

三项缺一不可。保存前可在设置里发一次短请求做连通测试；失败原因显示在设置页，不弹系统告警。

## 7. 单词本

只记词，不安排复习。没有熟悉度、到期日、抽认卡或打卡。

记入条件：

- 仅在本次查询成功后记入。失败不计数。
- 只记单词，不记句子或段落。判定用收尾空白修剪后的输入：不含空白、长度有限的一段即视为词。含空格的短语和整句不进单词本。
- 同一词合并为一条。拉丁字母大小写不区分，`Word` 和 `word` 是同一条；中文、日文按原文合并。

每条只存这些字段：

- 词面。展示用最近一次的写法。
- 计数。每成功查一次加一。
- 最近查询时间。多次查询只覆盖，不保留历史时间列表。
- 最近一次译文。方便导出后还能看懂；不存讲解全文，也不保留旧译文。

查看从菜单栏打开，单独一个普通窗口，不塞进悬浮小窗。默认按计数从高到低，计数相同再按最近查询时间从新到旧。可以按词过滤。可以删除单条。没有分组、标签、例句本。

导出一份 Markdown 文件，由用户选保存位置。按当前排序输出，每条一个小节，包含词、计数、最近查询时间、最近译文。不导出讲解全文。

## 8. 设置

菜单栏里打开，不占主面板。

- LLM 设置：Base URL、模型名、API Key
- 热键
- 目标语言
- 透明度
- 单词本
- 退出

不做账号体系、查询历史库、朗读、OCR、多协议供应商切换。

## 9. 明确不做

- 划词、选区抓取、Accessibility API
- 截图、OCR、屏幕录制
- 点击穿透，以及穿透和可输入之间的模式切换
- 鼠标悬停取词、剪贴板监听
- 系统词典离线库
- 复习、背单词、熟悉度、提醒、学习计划
- 句子级查询历史
- OpenAI Responses API，以及 Anthropic、Gemini 等非 `v1/chat/completions` 的私有协议
- Windows、Linux、移动端
- 自建后端

## 10. 验收

1. 启动后只有菜单栏图标，Dock 和 `⌘Tab` 里没有这个应用。
2. 热键呼出小窗。小窗在其他窗口之上，拖得动，透明度可调。
3. 在全屏播放或普通应用之上呼出后打字，菜单栏仍属于原来的应用。
4. 未完成 LLM 设置时提交查询，不发请求，面板提示先完成设置。
5. 配置 Base URL、模型名和 API Key 后，查询请求发往 `{Base URL}/v1/chat/completions`，面板流式出现译文和简短讲解。
6. 断网、密钥错误、接口报错时，面板内显示失败原因。
7. 系统设置里不需要辅助功能或录屏权限。
8. Esc 或再次点击菜单栏图标后小窗消失，进程仍在。
9. 成功查一个词后，单词本有该词，计数为 1，时间为本次查询时间。再查一次，计数为 2，时间改为最新一次。查一整句不产生单词本条目，失败的查询不计数。
10. 单词本可导出为 Markdown，文件中能看到词、计数、最近查询时间和最近译文。
